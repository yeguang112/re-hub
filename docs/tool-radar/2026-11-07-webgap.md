## 对 re-hub 的建议

1. **保留** `js-reverse-mcp` + Chrome CDP 作为 Web 主线，不因“缺口”引入 0★ 工具。
2. **可借鉴** `webcrypto-interceptor` 的观测点：`crypto.subtle` 入参/出参、Worker/iframe 附着、WASM dump、sourcemap 恢复、heap diff——补第 04/05 章的“加密参数定位”手法。
3. **可借鉴** `EleScrape` 的“CDP 抓包不装证书”思路，作为第 09 章代理抓包的轻量替代（注意它只覆盖浏览器内流量）。
4. `agent-ddp` 的“元素树 + 帧 + 检查”模型，可作为第 15 章 UI 复现的参考；但需要改 App 的 Debug build，暂不接。
5. `WRECK` 与 re-hub 同层，不接；关注它的“证据 → SPEC → 重建 → 验证”流程。
